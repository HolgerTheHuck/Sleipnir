# Sleipnir Error Catalog

> The authoritative catalog of Sleipnir's error codes and semantic categories.
> Companion to [`STABILITY.md`](STABILITY.md) §1.4 (error model) and
> [`PROTOCOL.md`](PROTOCOL.md) (wire format). Phase 1 — see
> [`docs/design/phase-1-interceptor-pipeline.md`](docs/design/phase-1-interceptor-pipeline.md).
>
> The error model is **two-layered**:
> - **Numeric `code`** (`SleipnirResponse.code` / `SleipnirError.code`) — HTTP-like status, stable
>   within 1.x (STABILITY.md §1.4). This is what 1.0.0 clients bind to.
> - **Semantic `category`** (`SleipnirError.category`, Phase 1, additive) — a machine-readable,
>   transport-uniform enum that lets clients handle errors without parsing HTTP status +
>   JSON-RPC code + domain code. Modeled on gRPC status codes to reduce polyglot
>   adoption friction.
>
> The two layers are *additive*, not replacing: the numeric code stays; the category layers on
> top. Existing 1.0.0 clients ignore `category` (it defaults to `None`) and keep working.

---

## 1. Numeric codes (`SleipnirErrorCodes`)

Stable within 1.x. Defined in [`SleipnirCommon/Results/SleipnirErrorCodes.cs`](SleipnirCommon/Results/SleipnirErrorCodes.cs).

| Code | Constant | Meaning | Generated by |
|---|---|---|---|
| 200 | `Ok` | Success | `SleipnirResults.Ok`, Invoker success path |
| 204 | `NoContent` | Success, no body (`void`/`Task` methods) | `SleipnirResults.NoContent`, Invoker void path |
| 400 | `BadRequest` | Invalid params, binding error, validation, dependency-chain break | Invoker `BuildParameters`, `ResolveParameterValues`, `ExplainUnavailability` |
| 401 | `Unauthorized` | Not authenticated (no/invalid identity) | `SleipnirResults.Unauthorized`, Invoker `CheckAuthorisation` (401 path) |
| 403 | `Forbidden` | Authenticated, but role/policy denied (Phase 1) | `SleipnirResults.Forbidden`, Invoker `CheckAuthorisation` (403 path), `SleipnirAuthorizationInterceptor` |
| 404 | `NotFound` | Controller/method not found (routing), or business not-found | Invoker routing (`Controller '/Method '`-prefix), `SleipnirResults.NotFound` (business) |
| 409 | `Conflict` | Conflict with current state (duplicate, stale version) | `SleipnirResults.Conflict` |
| 413 | `RequestEntityTooLarge` | Cardinality cap or message-size limit hit | Invoker `ExecuteMethod` (stream cap), `ReturnResponse` (result cap) |
| 499 | `ClientClosedRequest` | Client cancelled the request (transport-level) | REST transport (`OperationCanceledException` → 499) |
| 500 | `InternalServerError` | Unexpected server error (generic message in prod) | Invoker catch-all, `SleipnirResults.InternalServerError` |
| 503 | `ServiceUnavailable` | Overloaded / rate-limited | (reserved; rate-limiter produces 429 today, mapped to 503-category) |

**Stability:** the numbers and their meanings are fixed within 1.x (STABILITY.md §1.4). A
future error taxonomy extension layers *categories* on top, it does not renumber existing codes.

## 2. Semantic categories (`SleipnirErrorCategory`)

Additive (Phase 1). Defined in [`SleipnirCommon/Results/SleipnirErrorCategory.cs`](SleipnirCommon/Results/SleipnirErrorCategory.cs).
Defaults to `None` (1.0.0 responses have no category → backward compatible).

| Category | gRPC equivalent | Typical numeric code | Meaning |
|---|---|---|---|
| `None` | — | (any) | No category set (1.0.0 default). Clients must fall back to the numeric code. |
| `InvalidArgument` | `INVALID_ARGUMENT` | 400, 422 | Invalid params, binding, validation, type mismatch |
| `Unauthenticated` | `UNAUTHENTICATED` | 401 | Not authenticated (no/invalid identity) |
| `PermissionDenied` | `PERMISSION_DENIED` | 403 | Authenticated, but role/policy denied (Phase 1) |
| `NotFound` | `NOT_FOUND` | 404 | Routing or business not-found |
| `Conflict` | `ALREADY_EXISTS` / `FAILED_PRECONDITION` | 409 | Duplicate, stale version, state conflict |
| `FailedPrecondition` | `FAILED_PRECONDITION` | 400 | Dependency chain broken (provider failed, alias unavailable) |
| `ResourceExhausted` | `RESOURCE_EXHAUSTED` | 413, 429 | Cardinality cap, message-size limit, rate limit |
| `Internal` | `INTERNAL` / `UNKNOWN` | 500 | Unexpected server error |
| `Unavailable` | `UNAVAILABLE` | 503 | Overloaded, service unavailable |
| `Cancelled` | `CANCELLED` | 499 | Client cancelled the request |

**Stability:** the enum values and their names are stable within 1.x. New categories may be
added in minor versions (additive); existing ones keep their meaning.

## 3. How clients should handle errors

### 3.1 Simple clients (1.0.0-style — numeric code only)

```csharp
try { await rest.Call<Customer>(req); }
catch (SleipnirException ex)
{
    switch (ex.Error?.Code)
    {
        case 401: /* re-authenticate */ break;
        case 404: /* not found */ break;
        case 400: /* bad request — show ex.Error.Message */ break;
        default:  /* log and surface */ break;
    }
}
```

This continues to work unchanged. The numeric code is the stable, primary surface.

### 3.2 Category-aware clients (Phase 1 — recommended for new code)

```csharp
try { await rest.Call<Customer>(req); }
catch (SleipnirException ex) when (ex.Error?.Category == SleipnirErrorCategory.PermissionDenied)
{
    /* 403: authenticated but not allowed — show "insufficient permissions" */
}
catch (SleipnirException ex) when (ex.Error?.Category == SleipnirErrorCategory.Unauthenticated)
{
    /* 401: redirect to login */
}
catch (SleipnirException ex) when (ex.Error?.Category == SleipnirErrorCategory.NotFound)
{
    /* 404: render empty state */
}
```

The category is transport-uniform: REST, WebSocket, and SignalR all carry the same
`error.category` field. No need to switch on transport + code.

### 3.3 Generated clients (Phase 3-B — planned)

Codegen will emit typed exceptions per category (`SleipnirPermissionDeniedException`,
`SleipnirNotFoundException`, …) so the switch becomes type-based. Tracked in
[`ROADMAP.md`](ROADMAP.md) Benutzbarkeit-Roadmap Phase 3 (item B).

## 4. How controllers produce errors

Controllers return errors via [`SleipnirResults`](SleipnirCommon/Results/SleipnirResults.cs). The
factory sets both the numeric code and the category automatically:

| Factory method | Code | Category |
|---|---|---|
| `SleipnirResults.Ok(x)` | 200 | (none — success) |
| `SleipnirResults.NoContent()` | 204 | (none — success) |
| `SleipnirResults.BadRequest(msg)` | 400 | `InvalidArgument` |
| `SleipnirResults.Unauthorized()` | 401 | `Unauthenticated` |
| `SleipnirResults.Forbidden()` | 403 | `PermissionDenied` (Phase 1) |
| `SleipnirResults.NotFound(msg)` | 404 | `NotFound` |
| `SleipnirResults.Conflict(msg)` | 409 | `Conflict` |
| `SleipnirResults.InternalServerError(msg)` | 500 | `Internal` |
| `SleipnirResults.Error(code, msg, category, details)` | (custom) | (custom) |

**Rule of thumb:** don't `throw` to signal a business error — `return SleipnirResults.NotFound(...)`
etc. Throws become generic 500s with no message leak in production. See
[`BEST_PRACTICES.md`](BEST_PRACTICES.md) §1.2.

## 5. JSON-RPC compatibility mapping

When `EnableJsonRpcCompat = true`, the Sleipnir numeric code (or category) maps to a JSON-RPC
error code in `JsonRpcAdapter.MapErrorCode`:

| Sleipnir category | JSON-RPC code | JSON-RPC meaning |
|---|---|---|
| `InvalidArgument` | -32602 | Invalid params |
| `Unauthenticated` / `PermissionDenied` | -32001 | Server error (auth) |
| `FailedPrecondition` | -32602 | Invalid params (dep-chain) |
| `Internal` | -32603 | Internal error |
| `Unavailable` | -32003 | Server error (overload) |
| `NotFound` / `Conflict` / `ResourceExhausted` / `Cancelled` | -32000 | Server error (catch-all) |
| Routing-404 (`Controller '/Method '`-prefix) | -32601 | Method not found |

Without a category (`None`, 1.0.0 responses), the map falls back to the numeric code (v1.0
behavior). See [`JSONRPC_COMPAT.md`](JSONRPC_COMPAT.md).

## 6. OpenTelemetry tags

Errors are tagged on the `SleipnirCall` span (`SleipnirTracing`) and counted in metrics
(`SleipnirMetrics`):

- Span: `rpc.system=sleipnir`, `rpc.service`, `rpc.method`, `sleipnir.request_id`, plus
  `exception.type/message/stacktrace` on escaping exceptions.
- Metrics: `sleipnir.call.count` (Counter, tag `sleipnir.success`), `sleipnir.error.count` (Counter),
  `sleipnir.call.duration` (Histogram). Tag `sleipnir.error_category` carries the category.

See [`README_DETAILS.md`](README_DETAILS.md) *Distributed Tracing* and
[`docs/design/phase-1-interceptor-pipeline.md`](docs/design/phase-1-interceptor-pipeline.md).
